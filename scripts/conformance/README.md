# Cross-language conformance (`#171`)

Two structural frontmatter error strings —

- `invalid frontmatter: unterminated '---' block`
- `invalid frontmatter: expected a mapping at the top level`

— and the actor-derivation rules (`IsHumanActor` / `IsValidActor`) exist as
hand-copies across three implementations plus two prose fixtures, with nothing
binding them:

| copy | site |
|---|---|
| **Go — source of truth** | `internal/okf/native/native.go`, `internal/okf/trust.go` |
| TypeScript | `packages/astro-okf/src/parse.ts`, `packages/astro-okf/src/trust.ts` |
| Python — the validation gate | `scripts/frontmatter_parse.py` (run by `scripts/validate-plugin.sh`) |
| prose | `scripts/testdata/plugin-validate/{unterminated,nonmapping}/SKILL.md` |

Before `#171`, editing a Go string broke **no** suite: the TS assertions matched
the TS source, the Python gate matched itself, and the prose matched nobody. The
copies stayed green while diverging from Go.

## How this check binds them

`Go is the single source of truth, and the expected values are DERIVED FROM IT
at run time — never hand-copied here.`

1. `corpus.json` holds **inputs only** (frontmatter documents, actor strings).
2. `internal/okf/conformance/gogolden` runs the **real** Go code over those
   inputs (`native.Codec.ParseConcept`, `okf.IsHumanActor`, `okf.IsValidActor`)
   and prints the golden — the actual error text and actor booleans Go produces.
3. Each other copy is diffed against that golden:
   - `ts-conformance.mjs` — the shipped `dist` (parse.ts + trust.ts);
   - `py-conformance.py` — imports the **same** `frontmatter_parse.py` the gate
     runs;
   - `prose-conformance.py` — asserts each prose fixture still restates the
     current Go phrase.

Because the golden is generated by executing Go, editing a Go string or actor
rule changes it automatically, and every copy that failed to follow goes **red**
— once per copy.

## Running

```sh
npm run build --workspace astro-okf        # TS is checked against dist
make conformance                           # or: scripts/conformance/cross-language-conformance.sh
```

Requires `go`, `node`, and `python3` with PyYAML. Wired into CI as the
`conformance` job in `.github/workflows/ci.yml`.

## Proving it actually fails (negative fixture)

`negative-fixture.sh` is the permanent, automated negative test: it mutates the
Go source, asserts the check goes red **once per copy** (TS, Python, and both
prose fixtures), reverts and requires green, then does the same for a `trust.ts`
actor-rule divergence. It restores every file it touches. It runs in CI right
after the positive check.

## Scope / residual

This check binds the two structural error strings and the two actor predicates
named in `#171`. The parser-dependent wrapped-YAML error path
(`invalid frontmatter: <parser message>`) is intentionally **not** cross-checked
— PyYAML, `yaml` (JS), and `gopkg.in/yaml.v3` word those differently — and
`deriveTier` / `isStale` are covered only transitively. See the tracked residual
referenced from the breadcrumb in `internal/okf/conformance/gogolden/main.go`.
